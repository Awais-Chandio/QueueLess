# 1A.6 Public token status

## Goal
Anyone holding a token code (including guests without an account) can see where they are in the queue, and
nothing else.

## What the migration adds
`get_token_status(p_public_code text)`: `STABLE SECURITY DEFINER`, granted to `anon` and `authenticated`.
Returns **exactly** `token_number, people_ahead, eta_minutes, current_token, doctor_name, status`:
- `people_ahead` / `eta_minutes` / `current_token` come from `private.token_progress` (1A.5).
- `doctor_name` = `doctors.name` (NULL for a center queue without a doctor).
- `status`: `waiting` (pending/confirmed/checked_in) · `called` · `in_progress` · `completed` · `cancelled` ·
  `missed` (no_show/expired).

## Decisions (safest option)
- **No patient name, phone, email, appointment/patient/center id, date or time** is returned, ever. A test runs
  the status for every appointment in the database and fails on any of those values or any extra field.
- **Unknown, malformed, NULL or injection-shaped codes return no row** (no error), so "wrong format" and
  "no such token" can't be told apart. Code input is trimmed and upper-cased.
- Read-only (`STABLE`): a status lookup can't change anything.
- No lookup rate limit: codes are 40-bit random (≈1.1 × 10¹² values), so guessing a live code is impractical.
  Put an edge rate limit in front of the public page anyway (Phase 1B).
