# 0.3 Lock down RPCs

## Goal
No function in `public` is callable by anon. Signed-in users can call only the RPCs the app uses,
and each RPC that touches another person's data checks the caller. Every app function runs with
`search_path = ''`.

## What the migration does
1. **`private` schema helpers** (not exposed by PostgREST): `is_server_context()`, `is_center_staff()`,
   `can_manage_center()`, `is_doctor_self()`, `can_manage_doctor()`, `can_operate_appointment()`,
   `can_view_appointment()`. Center scope comes from `staff_centers`; the role comes from
   `is_admin()` / `is_staff()`.
2. **Caller checks** (raise `42501`):
   | Function | Allowed |
   |---|---|
   | `confirm_appointment`, `start_service`, `call_appointment` | staff of the appointment's center, its doctor, admin |
   | `set_center_break`, `update_center_average_consultation_time` | staff of that center, admin |
   | `refresh_live_queue` | trigger calls; otherwise that doctor, staff of their center, admin |
   | `recalculate_doctor_average` | that doctor, staff of their center, admin |
   | `cleanup_stale_appointments` | server only (no client grant, plus a role check) |
   | `get_center_queue_snapshot` | center staff/admin, a doctor there, a patient with an appointment there that day |
   | `get_doctor_queue_snapshot` | that doctor, staff of their center, admin, a patient booked with them that day |
   | `get_appointment_queue_snapshot`, `people_ahead(uuid)` | the appointment's patient, center staff, its doctor, admin |
   | `get_doctor_today_appointments`, `_recent_patients`, `_income_summary` | that doctor, admin |
   | `staff_performance` | admin |
   "Server" means no app role is behind the call (service_role, pg_cron, SQL editor).
3. **`search_path = ''` on all 59 public functions** (the 17 advisor hits, plus the rest pinned
   from `public` to `''`). 41 keep identical logic and only have references schema-qualified
   (31 lines). Verified with `plpgsql_check` and SQL-body validation under an empty search_path.
4. **Policies** that call `is_admin()`/`is_staff()` move from `PUBLIC` to `authenticated` (11 policies,
   conditions unchanged). Otherwise anon queries would hit "permission denied for function".
5. **EXECUTE**: revoked from PUBLIC/anon/authenticated on every public function. Granted to
   `service_role` on all, and to `authenticated` on the 23 RPCs the app calls plus `is_admin`/`is_staff`.
   Default privileges: `ALTER DEFAULT PRIVILEGES FOR ROLE postgres REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC`.
   The requested `... IN SCHEMA public ...` form is included too, but **on its own it does nothing**:
   a per-schema default can't remove a global one. Verified locally (new function: anon
   EXECUTE `true` with the per-schema form only, `false` with the global one).

## Bugs fixed on the way (they already break on live)
- `cancel_appointment` wrote `'patient'` into `cancelled_by` (uuid), so it **always failed**, and the
  app silently fell back to a direct UPDATE. It now stores `auth.uid()`.
- `get_doctor_availability` read the retired `doctor_availability` table, so it **always failed**.
  It now reads `doctor_schedules` (`slot_duration_minutes`).

## Found, not fixed (later phases)
- `cleanup_stale_appointments` sets `confirmed → no_show`, which
  `validate_appointment_status_transition` forbids, so it fails whenever there is stale work
  (Phase 1D, together with pg_cron).
- `log_appointment_status_change()` writes to a table that doesn't exist; no trigger uses it.
- `trigger_queue_notification` posts to `http://kong:8000/...`, a local-Docker address that hosted
  Supabase can't reach (0.6).
- `current_token_view` / `queue_view` run with the owner's rights (`security_invoker` off). That's an
  advisor error; no client role has SELECT on them. Fixed in 0.4.
