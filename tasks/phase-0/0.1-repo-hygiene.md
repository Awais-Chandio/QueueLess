## Plan
1. Untrack `.env`, update `.gitignore`, add `.env.example`:
   ```
   SUPABASE_URL=https://<project-ref>.supabase.co
   SUPABASE_ANON_KEY=<anon-or-publishable-key>
   ```
2. Install `react-native-config`. iOS: `pod install`, which autolinks and reads `.env` at build time.
   Android: add `apply from: project(':react-native-config').projectDir.getPath() + "/dotenv.gradle"`.
   - Why not `react-native-dotenv` (Babel only)? It needs no native rebuild, but `react-native-config`
     can also feed native config (Maps key, Sentry in 0.7) and supports `ENVFILE=.env.staging`.
     Note that both bake values into the binary, which is fine because the anon key is public by design.
3. `supabase.ts`: read `Config.SUPABASE_URL` / `Config.SUPABASE_ANON_KEY`, with **no fallback**.
   The `supabaseConfig.isValid` check and the error screen in `App.tsx` already handle missing values.
4. Jest: add `jest.mock('react-native-config', () => ({ SUPABASE_URL: 'http://localhost:54321', SUPABASE_ANON_KEY: 'test' }))`.
5. Delete the credential scripts and junk, and remove the `accounts:production` npm script.
6. Prepare (do not run) the `git filter-repo` commands and the owner follow-ups (below).
7. Commit: `chore(security): untrack .env, move Supabase config to env, remove credential scripts`.

## History purge (owner runs; NOT run by Claude)
Run this in a **fresh mirror clone** so the working copy is untouched:
```bash
pip install git-filter-repo         # or: brew install git-filter-repo
git clone --mirror https://github.com/Awais-Chandio/QueueLess.git QueueLess-purge.git
cd QueueLess-purge.git
git filter-repo --invert-paths \
  --path .env \
  --path add_doctor_schedule.js --path check_doctor.js \
  --path inspect_db.js --path inspect_live_db.js --path print_admin_role.js \
  --path scripts/manage-production-accounts.js \
  --path .rbac-backup/ --path ts-errors.txt --path testDashboard.js
# Also scrub the anon key that was hard-coded in src/lib/supabase.ts history:
#   echo 'eyJ...full-anon-key...==>REDACTED_SUPABASE_ANON_KEY' > ../replacements.txt
#   git filter-repo --replace-text ../replacements.txt
git push --force --mirror origin
```
Then ask GitHub Support to purge cached views and PR refs (`refs/pull/*` can't be rewritten by a push).

Before the purge, merge `phase-0-security` (or push it) so it gets rewritten with everything else.
Otherwise the rewritten `main` and this branch no longer share history.

### Re-cloning on your other machines (after the force-push)
Old clones still hold the secrets and **must not be pushed**: one `git push` from an old clone
would put the purged commits back. On each machine:
```bash
cd /path/to/QueueLess
git status                               # 1. anything uncommitted?
git stash -u                             #    if so, park it (or copy files out)
cp .env ~/queueless.env.bak              # 2. keep your local .env (it is untracked now)
cd ..
mv QueueLess QueueLess-OLD-do-not-push   # 3. keep the old copy until you've verified
git clone https://github.com/Awais-Chandio/QueueLess.git
cd QueueLess
cp ~/queueless.env.bak .env              # 4. restore env
npm install && (cd ios && pod install)   # 5. reinstall deps / pods
git log --all --oneline -- .env          # 6. must print nothing
```
- Uncommitted work from the old copy: copy the changed **files** across. Don't `git pull`,
  merge or cherry-pick from the old clone, because that brings back old commits.
- Once the new clone builds, delete `QueueLess-OLD-do-not-push` and `~/queueless.env.bak`.
- Other forks or clones you don't control (collaborators, CI caches) still have the old history.
  That's why rotating the passwords matters more than the purge.
