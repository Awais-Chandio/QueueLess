# 0.7 Observability

## Goal
Production builds don't write debug logs (several contain profiles, emails, tokens or OTP codes).
Crashes and render errors are caught at the root and reported to Sentry.

## Findings
- `ErrorBoundary` exists (`src/components/ui/ErrorBoundary.tsx`) but is **not mounted** anywhere.
- `RootNavigator` logs the **full profile**, role and route on every change, in production too.
- 276 `console.*` calls (143 log, 88 warn, 45 error); roughly 225 aren't on the same line as a
  `__DEV__` check. Some log PII: profile objects, emails, user IDs, booking payloads, and the OTP code in
  the (now disabled) phone flow.

## Owner setup (needs your Sentry account)
1. Create a Sentry project (platform: React Native) and copy its DSN into `.env` as `SENTRY_DSN=`.
   The DSN is a public ingest key, so it's safe in the app, unlike an auth token.
2. Source maps and native symbols (readable stack traces): run `npx @sentry/wizard@latest -i reactNative`.
   It adds the Gradle plugin, the Xcode build phase and `sentry.properties`, and asks for an **auth token**.
   Keep that token out of git: use `SENTRY_AUTH_TOKEN` in your shell/CI, not `sentry.properties`.
3. In Sentry → Project Settings → Security & Privacy: turn on "Data Scrubber" and "Use Default Scrubbers".
