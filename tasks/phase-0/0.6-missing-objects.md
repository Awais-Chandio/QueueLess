## What the migration adds
1. **doctor_reviews** plus `doctors.avg_rating` / `review_count`, kept in sync by a trigger. Doctors can't
   edit their own aggregates. Based on the archived file, with changes:
   - **No anon access** (was public, including anon).
   - **`patient_id` isn't client-readable** (column grants). Every signed-in user can read reviews, and
     `patient_id + doctor_id` would reveal who saw which doctor.
   - Insert only by the patient of a *completed* appointment, for that doctor, once.
2. **visit_summaries**, **prescription_items**, **`save_visit_summary()`** (SECURITY INVOKER, so RLS applies):
   only the assigned doctor writes, on completed visits; only that patient, that doctor and admins read.
   Staff can't read clinical summaries.
3. **`busiest_services`, `busiest_centers`, `bookings_per_day`**: SECURITY DEFINER and admin-only (the
   archived version granted them to anon).
4. **Realtime**: `appointments`, `center_queue_settings`, `doctor_queue_settings` added to `supabase_realtime`
   (only if not already there).
All functions use `search_path = ''`, and grants are explicit (new functions start with no PUBLIC EXECUTE).

## Additions: `20261021101710_edge_function_grants_drop_kong_trigger.sql`
- **service_role** gets `SELECT` on `device_tokens`, `center_queue_settings`, `appointments`: exactly what
  `send-queue-notification` reads. Before, it had only REFERENCES/TRIGGER/TRUNCATE, so its reads failed.
  *Decision (safest):* read-only, those three tables only. Phase 1D adds more if the rebuild needs it.
- **kong:8000 pg_net call removed**: dropped `queue_notification_trigger` and `trigger_queue_notification()`.
  The URL only resolves inside local Docker, so on hosted Supabase every status change made a call that
  failed silently. *Decision:* drop the function too, so the URL can't be re-attached. Push notifications
  are rebuilt in Phase 1D; in-app notifications (notifications table) are unaffected.
- Tests: `05_edge_function_and_triggers.test.sql` (7 checks). Full suite **149/149**.
- Security lints (local): 28× "authenticated can execute SECURITY DEFINER" (the app RPCs incl. the 3
  admin analytics, all with caller checks), 1× pg_net in public. No ERRORs, nothing for anon.
